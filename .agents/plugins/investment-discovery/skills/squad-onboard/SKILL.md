Main Dot conducts onboarding and setup directly. This checklist owns order/questions; references own implementation details.

1. First prerequisite: discover environment-management tools; list environments and attach returned ID described **This Dot’s cloud computer**. If absent, guide user: select Dot icon atop conversation → **Your dot’s computer**. Recheck and attach. [Computer access](references/cloud.md#computer-and-command-access) owns permissions and actual write checks.
2. Reuse supplied facts; gather remaining choices in one concise batch: repository page URL plugin downloaded from; country/jurisdiction; market/allowed investments; currency; brokerage; risk/loss restrictions; message destination; timezone and each workflow's cadence. Suggest daily research, daily monitoring after selected markets close, weekly reconciliation; ask preferred times. Research public broker fees/restrictions; present supported defaults for review. Keep countries, currencies and brokers user-specific.
3. Include storage proposal in same batch: private Ladybug research + SQLite predictions/results + sources on this computer outside checkout; private connected Drive folder; one backup file updated in place; normal Drive version history/expiry; project/archive byte budgets; financial-data access and computer-loss recovery limits. Obtain acceptance before creating stores. [Storage](references/storage.md) owns details.
4. Resolve user's repository, including forks, and downloaded release/version. If unresolved, ask release page/version. Clone/reuse verified checkout on attached computer; read its AGENTS.md. [Setup](references/setup.md) owns paths/runtime preparation.
5. Discover connected Drive integration. If missing, offer normal connection flow; rediscover tools afterward. Actual `get_profile` read confirms connection. Create/select reviewed private folder, collect complete inventory, preserve returned IDs/receipts. [Connected Drive](references/cloud.md#connected-drive) owns tool discovery.
6. Fill project `.env` from `.env.example` with reviewed [configuration](references/configuration.md): choices, costs, risk, private paths, folder/budgets and all three schedules. Agent edits file directly; verify separate command session and Python child receive values through [explicit loading](references/cloud.md#project-environment).
7. After storage acceptance, run `init --inventory FILE`. Existing backup requires recovery. Record original installation identity; run `doctor`. [Storage](references/storage.md) owns initialization/recovery.
8. Prepare/upload first backup through connected Drive tools; record upload acceptance separately from folder creation, initialization and deliberate recovery testing. Preserve pending operation after failure.
9. Create/update [scheduled automations](../squad-reconcile/references/deployment.md#scheduled-automations) from saved configuration; each invokes relevant skill on same computer/original stores with explicitly loaded project `.env`. Preserve user pauses. Distinguish saved automation from observed successful wake/run; use documented fallback when immediate test unavailable.
10. Research through [one-shot method](../squad-research/references/methodology.md); track qualified ideas using [future predictions](../squad-monitor/references/validation.md). User-pasted current portfolio/cash starts each next-action advice request through squad-trades. User controls Dot's operation and schedules.
11. Send user concise setup status via `user_message.send_message`, `channel="chatgpt"`; save returned message reference privately. Report computer/release, original store identity, backup acceptance, recovery-test status, automation IDs/observed runs and blockers accurately. App settings determine push delivery. Keep conversation with main Dot; explain any test artifact retained because deletion requires permanent-delete approval.
