After update start a fresh process, install pinned dependencies/setup-runtime if changed, run relevant required checks, refresh actual cached marketplace/plugin through supported host controls and verify loaded contents.
3. Run deployment plan. Dirty/untracked source cannot be recorded. Stable task keys and thin prompts describe expected runtime/cadence/timezone/model settings; they are not a platform import manifest. Native-config prompts must not copy personal values/credentials or invent a profile file.
4. List actual native tasks; normalize actual returned values/IDs per docs/GITOPS.md into a private observation. Match only this profile's SQUAD_TASK_KEY. deployment plan --observed FILE computes actions. Preserve unrelated tasks, resolve duplicate keys by pausing extras, reuse native IDs for updates, pause obsolete project tasks.
5. Apply only through real supported tools. Unsupported runtime/model/schedule fields block activation, never manufacture matching readback. After uncertain responses inspect actual state before retry.
6. Read back actual tasks and loaded skill digest. Independently execute a saved owner probe reopening both original graph/ledger paths, returning matching setup identities/runtime. Retain actual run receipt. Send a labelled setup notification to configured destination with real delivery confirmation; never acknowledge a real qualification for setup. Make a current backup cloud with actual upload/download/staging restore verification.
7. Write fresh actual readback/probe/delivery observations privately; deployment record --file FILE validates source, drift, identities, freshness and actual verified-backup event. CLI cannot independently authenticate supplied platform JSON; use actual tool observations. Missing evidence leaves inactive. Second deployment check --observed FILE should show CURRENT/no actions.

Keep cadence/ref user-reviewed; fast-forward reconciliation is mandatory. Restore invalidates cached deployment despite unchanged code/signature; reconcile post-backup delivery ambiguity, obtain fresh owner/task/notification proofs and verified backup. Rollback only to compatible reviewed code with refreshed skills/tasks; never rewind prediction evidence. Unknown/newer schema requires deliberate recovery/migration, not reset. Admin-only GitHub sync is outside this deployment workflow.
