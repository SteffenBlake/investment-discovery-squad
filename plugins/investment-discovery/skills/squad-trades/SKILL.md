Run knowledge context --portfolio PRIVATE_FILE --query RELEVANT_TERMS. Read bounded graph/text evidence, source dates/provenance, contradictions, validity, coverage gaps and numerical signal summaries. Broaden search/hops or retrieve exact records when truncated/materially incomplete. The LLM reasons about buy/hold/sell/avoid; no separate optimizer is required. Missing knowledge is not proof of safety. Fetch current public data when material facts need refreshing.

Supplied actual portfolio and recorded ledger remain distinct. Context never changes cash or fabricates fills. Explain discrepancies and reconcile actual user-reported transactions before cash-sensitive sizing. No graph claim/confidence bypasses historical/live qualification. Use report --signal ID for complete outcomes; preserve every loss/pending prediction and uncertainty.

For a fresh qualified bullish forecast run idea --prediction ID; production deployment gate applies. Python checks configured cash/currency/lots/tick/expiry/daily cap. Qualification alone is not an entry. Explain symbol/venue, side/quantity, quote source/time/delay, proposed limit/notional/currency, rationale, objective/horizon, exit/invalidation review and skip conditions. No guarantee of price/fill/return. User verifies live spread, fees, actual settled buying power, pending orders and account restrictions, then executes themselves.

Record only actual reported fills with unique fill_id, symbol/side/quantity, configured-currency price/fee and timestamp using fill --file. Separate partial IDs; exact retry is idempotent. Chat approval/unfilled order is not a fill. Review exits at horizon/invalidation and retain actual follow-up receipts to avoid duplicate reminders. Forecast success is not actual trade P&L. FX, taxes, settlement, transfers and margin are outside this ledger; explain when relevant. After actual fills/new evidence and alert handling run backup-due; preserve recovery errors/ambiguity.
